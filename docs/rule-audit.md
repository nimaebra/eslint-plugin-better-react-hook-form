# Rule rationale and roadmap

Reviewed October 30, 2026 against React Hook Form v7 documentation, upstream fixes, releases, and the dot-skills React Hook Form guide. The plugin supports RHF >=7.55.0 <8. Syntax-only analysis must prefer missed uncertain cases over false positives.

The v1 review retains the original eleven rules and existing preset severities. Three new correctness rules are individually opt-in and enabled as errors in `all`. Strict-only membership is explicit in the registry, so adding a rule cannot silently expand `strict`.

## Rule decisions

| Rule                                       | Decision            | Evidence and limits                                                                                                                                                                                                                                                                                                                                         |
| :----------------------------------------- | :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| destructuring-formstate                    | Excluded            | [formState](https://react-hook-form.com/docs/useform/formstate) supports direct reads; subscription timing and conditional reads are the actual concern.                                                                                                                                                                                                    |
| no-use-watch                               | Excluded            | [watch](https://react-hook-form.com/docs/useform/watch) remains supported. Compiler-specific alternatives should not ban ordinary usage.                                                                                                                                                                                                                    |
| no-values-with-shouldunregister            | Excluded            | [Issue 12697](https://github.com/react-hook-form/react-hook-form/issues/12697) was resolved by [a9b8a6f](https://github.com/react-hook-form/react-hook-form/commit/a9b8a6fb919c7ec9e0ea671b64712e1c39fc9f15); [issue 13314](https://github.com/react-hook-form/react-hook-form/issues/13314) is also closed. Do not preserve bugs as permanent usage rules. |
| no-deprecated-watch-callback               | Recommended warning | [watch](https://react-hook-form.com/docs/useform/watch) deprecates the callback overload; [subscribe](https://react-hook-form.com/docs/useform/subscribe) is available from v7.55.0. Migration changes callback and cleanup shapes, so no autofix.                                                                                                          |
| no-double-register                         | Recommended error   | [Controller](https://react-hook-form.com/docs/usecontroller/controller) warns against double registration. Report proven field/register spreads on the same element only.                                                                                                                                                                                   |
| no-empty-usefieldarray-action              | Recommended error   | [useFieldArray](https://react-hook-form.com/docs/usefieldarray) requires row data. Track method origins and explicit empty/undefined values; do not infer required row properties.                                                                                                                                                                          |
| no-form-methods-object-in-deps             | Recommended error   | [FormProvider](https://react-hook-form.com/docs/formprovider) documents individual methods in dependencies. A separate formState object is valid.                                                                                                                                                                                                           |
| no-nested-form-provider                    | Recommended warning | [FormProvider](https://react-hook-form.com/docs/formprovider) advises avoiding nested providers. Deliberately independent forms can override the warning.                                                                                                                                                                                                   |
| no-register-bracket-syntax                 | Recommended error   | [register](https://react-hook-form.com/docs/useform/register) specifies dot paths. Only unambiguous literal conversions receive fixes.                                                                                                                                                                                                                      |
| no-stacked-usefieldarray-actions           | Strict warning      | [useFieldArray](https://react-hook-form.com/docs/usefieldarray) discourages consecutive actions. Group the same hook instance in consecutive synchronous statements; skip uncertain control flow.                                                                                                                                                           |
| prefer-useformstate-over-formstate-context | Strict warning      | [useFormContext](https://react-hook-form.com/docs/useformcontext) recommends useFormState for subscriptions. Treat this as optional subscription/performance advice.                                                                                                                                                                                        |
| usefieldarray-require-field-id-key         | Recommended error   | [useFieldArray](https://react-hook-form.com/docs/usefieldarray) requires the generated key. Respect custom v7 keyName and skip unknown spread-provided keys.                                                                                                                                                                                                |
| no-conflicting-value-transforms            | Recommended error   | [register](https://react-hook-form.com/docs/useform/register) explains ignored setValueAs transforms. Report proven conflicts after spread/override resolution; choosing the intended transform is not automatic.                                                                                                                                           |
| no-undefined-controller-default-value      | Recommended error   | [Controller](https://react-hook-form.com/docs/usecontroller/controller) disallows undefined defaults. Do not require a field-local default when useForm.defaultValues supplies one.                                                                                                                                                                         |

## Prioritized future work

| Release / priority | Deliverable                                                                      | Acceptance boundary                                                                                                                                                                                   |
| :----------------- | :------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.0.x              | False positives, unsafe fixes, compatibility regressions and clearer diagnostics | Reproduce each consumer report; add a valid-case regression; retain public exports and document behavior changes.                                                                                     |
| Future minor       | Existing-rule enhancements                                                       | Support stable aliases of registration results for double-registration detection and more directly provable JSX return patterns for field keys. Add valid-case regressions before widening detection. |

New rules start as individually opt-in rules and all-preset errors. Additions to recommended or strict require a major release after consumer fixtures and false-positive feedback support the change. Include docs, diagnostics, scope/alias cases, installed consumers and a changeset with each rule, following the [versioning policy](../README.md#versioning).

## Research backlog

- Controller value transforms: consider a separate `no-unsupported-controller-rules` rule for explicit valueAsNumber/valueAsDate/setValueAs options. Both [v7.55 types](https://github.com/react-hook-form/react-hook-form/blob/v7.55.0/src/types/controller.ts) and [v7.91 types](https://github.com/react-hook-form/react-hook-form/blob/v7.91.0/src/types/controller.ts) exclude these keys. Ordinary field.onChange bypasses conversion, but other update paths can use stored options; do not claim they never execute. No autofix. [Controller implementation](https://github.com/react-hook-form/react-hook-form/blob/v7.91.0/src/useController.ts)
- Resolver plus form-level validate: establish per-version semantics and limit analysis to proven properties on the same options object. [useForm](https://react-hook-form.com/docs/useform)
- Controller shouldUnregister within a field array: prove the array/name/control relationship rather than globally banning the prop. [Controller](https://react-hook-form.com/docs/usecontroller/controller)
- Conditional formState subscriptions: distinguish render short-circuit gaps from valid direct reads and effect dependencies. This requires narrow control-flow analysis. [formState](https://react-hook-form.com/docs/useform/formstate)
- RHF v8: keep the peer range below 8 until a separate stable-API review and compatibility matrix exist. Beta changes to generated keys, keyName, callback watch and payload semantics prevent reusing v7 rules unchanged. [v8 beta.5](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.5)

## Upstream issues are evidence, not permanent prohibitions

The stable baseline reviewed is [v7.91.0](https://github.com/react-hook-form/react-hook-form/releases/tag/v7.91.0). [Issue 13816](https://github.com/react-hook-form/react-hook-form/issues/13816) and its [fix 13817](https://github.com/react-hook-form/react-hook-form/pull/13817) concern library reset behavior, so they do not justify universally adding reset options. Likewise, [PR 13951](https://github.com/react-hook-form/react-hook-form/pull/13951) and [PR 13954](https://github.com/react-hook-form/react-hook-form/pull/13954) address async validation races rather than establishing that consumers should avoid asynchronous validation.

New rules need a primary source, useful diagnostics, valid-case coverage, and reproducible package tests. Runtime relationships and unreleased features remain deferred until they can be checked precisely.

### Corrections and compatibility boundaries

- `[formState]` is a documented valid effect dependency. Do not extend the methods-object rule to reject it. Reading individual properties, directly or by destructuring, establishes subscriptions; destructuring itself is not mandatory. [Official formState guidance](https://react-hook-form.com/docs/useform/formstate)
- Exceptions from the success callback do not leave `isSubmitting` stuck: both supported-version endpoints catch the error, update submission state, then rethrow. Root server errors do not persist across submissions as the skill claims. These facts do not remove the need for application-level error presentation. [v7.55 source](https://github.com/react-hook-form/react-hook-form/blob/v7.55.0/src/logic/createFormControl.ts), [v7.91 source](https://github.com/react-hook-form/react-hook-form/blob/v7.91.0/src/logic/createFormControl.ts), [setError documentation](https://react-hook-form.com/docs/useform/seterror)
- Async defaults are cached. Replacing an effect dependent on a record ID changes behavior unless refreshing is handled separately. The values option uses deep equality, rather than resetting merely because a reference changes. [useForm documentation](https://react-hook-form.com/docs/useform), [v7.91 implementation](https://github.com/react-hook-form/react-hook-form/blob/v7.91.0/src/useForm.ts)
- `resetDefaultValues`, render-prop wrappers, field-array disabled options, and per-setValue delayError options are not all available throughout >=7.55.0 <8. They cannot become unconditional migration targets while retaining that peer range. [v7.55 public types](https://github.com/react-hook-form/react-hook-form/blob/v7.55.0/src/types/form.ts), [current field-array API](https://react-hook-form.com/docs/usefieldarray), [current setValue API](https://react-hook-form.com/docs/useform/setvalue)
