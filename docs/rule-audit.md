# Rule audit and roadmap

Reviewed October 29, 2026 against React Hook Form v7 documentation, upstream fixes, and releases. The plugin supports RHF >=7.55.0 <8. Syntax-only analysis must prefer missed uncertain cases over false positives.

## Current rules

| :----------------------------------------- | :--------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| destructuring-formstate                    | Remove                 | [formState](https://react-hook-form.com/docs/useform/formstate) supports direct reads; subscription timing and conditional reads are the actual concern.                                                                                                                                                                                                    |
| no-use-watch                               | Remove                 | [watch](https://react-hook-form.com/docs/useform/watch) remains supported. Compiler-specific alternatives should not ban ordinary usage.                                                                                                                                                                                                                    |
| no-values-with-shouldunregister            | Remove                 | [Issue 12697](https://github.com/react-hook-form/react-hook-form/issues/12697) was resolved by [a9b8a6f](https://github.com/react-hook-form/react-hook-form/commit/a9b8a6fb919c7ec9e0ea671b64712e1c39fc9f15); [issue 13314](https://github.com/react-hook-form/react-hook-form/issues/13314) is also closed. | no-deprecated-watch-callback               | Recommended warning    | [watch](https://react-hook-form.com/docs/useform/watch) deprecates the callback overload; [subscribe](https://react-hook-form.com/docs/useform/subscribe) is available from v7.55.0. Migration changes callback and cleanup shapes, so no autofix.                                                                                                          |

## Follow-up candidates

1. **Undefined setValue arguments.** [setValue](https://react-hook-form.com/docs/useform/setvalue) requires a defined value. Limit a future rule to proven RHF calls and explicitly undefined or missing arguments; never guess a replacement.
2. **Field-array unregister relationships.** [Controller](https://react-hook-form.com/docs/usecontroller/controller) warns about shouldUnregister during array remount/reorder. A rule must prove the relevant array/Controller relationship rather than ban shouldUnregister globally.
3. **Resolver/form-level validation conflicts.** [useForm](https://react-hook-form.com/docs/useform) and [v7.72.0](https://github.com/react-hook-form/react-hook-form/releases/tag/v7.72.0) describe form-level validation. Design version-aware checks before recommending this to older v7 consumers.
4. **Conditional formState subscriptions.** [formState](https://react-hook-form.com/docs/useform/formstate) illustrates short-circuit subscription gaps. Require a narrow control-flow analysis that permits valid render reads and effect subscriptions; do not restore a blanket destructuring rule.
5. **RHF v8 support.** [v8.0.0-beta.5](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.5) changes field.id to field.key, removes keyName and callback watch, and changes row payload semantics. Add explicit version selection and consumer matrices after stable API review; do not claim beta compatibility now.

## Upstream issues are evidence, not permanent prohibitions

The stable baseline reviewed is [v7.91.0](https://github.com/react-hook-form/react-hook-form/releases/tag/v7.91.0). [Issue 13816](https://github.com/react-hook-form/react-hook-form/issues/13816) and its [fix 13817](https://github.com/react-hook-form/react-hook-form/pull/13817) concern library reset behavior, so they do not justify universally adding reset options. Likewise, [PR 13951](https://github.com/react-hook-form/react-hook-form/pull/13951) and [PR 13954](https://github.com/react-hook-form/react-hook-form/pull/13954) address async validation races rather than establishing that consumers should avoid asynchronous validation.

New rules need a primary source, useful diagnostics, valid-case coverage, and reproducible package tests. Runtime relationships and unreleased features remain deferred until they can be checked precisely.

## Dependency audit

The October 29 lockfile removes stale playground entries and uses patched brace-expansion, fast-uri, js-yaml, source-map-js, and Vite releases. `pnpm security:audit` passes the moderate-or-higher gate. One [low-severity deepmerge advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) remains through the development-only documentation generator; npm reports no patched version. It is not a runtime package dependency, and the advisory is not suppressed.
